# grill の問い詰めワークフロー

**なぜそうするかは[問い方の規律](questioning.md)にある。ここは手順である。**

## 先に調べる

問いを立てる前に、手元で分かることを潰す。コード・既存文書・履歴を確認し、調べて分かったら「この前提でいく」と宣言して進む。黙って前提にしない。

## 1問ずつ詰める

依頼または呼び出し側の指示から受け取った背景・前提・目的・着眼点に沿って調べる。曖昧・未決が見つかったら、いま問える1問にする。推奨回答と理由を必ず添え、相手が確認か修正だけで進める状態にする。

答えを待ってから次へ進む。前の答えで次の問いが変わるため、一度に大量の問いを出さない。

## 決めたことを記録する

```bash
python3 "${PLUGIN_ROOT}/scripts/decision.py" add --config "$CFG_FILE" \
  --topic "<題材>" --aspect "<観点>" --what "<決めたこと>" --why "<理由>"
```

後でまとめて書かない。その場の理由は時間が経つと再現できない。理由が空だと書けない。

statusは記録するその瞬間に選ぶ。

- `decided`: 合意した内容と理由を、その場で記録する（既定）。
- `open`: 決められない論点を未決のまま残す。無理に決めない。判断者が不在なら誰の判断待ちかを、試さないと決まらないなら何を試せば決まるかを、理由に書く。
- `dropped`: 取り下げた理由を残し、同じ論点の再発を防ぐ。

## 合意を要約する

```bash
python3 "${PLUGIN_ROOT}/scripts/decision.py" render --config "$CFG_FILE" --topic "<題材>"
```

決定・未決・取り下げを並べて見せる。未決が残っていることを隠さない。

## 合意で閉じる

**問える問いが尽きても、この工程はまだ終わっていない。** render の出力を提示し、**相手が合意したと言うまで閉じない。**

合意が出たら、そこで止める。未決が残ったまま合意することはあるが、合意のないまま実装や資料作成へ進むことはない。
